# Security Foundations of Randomness

## Why Randomness Is Critical to Cybersecurity:
Randomness is an essential part of security systems, as they rely on secret values and protocol messages that attackers aren't able to predict. A true random number generator (TRNG) draws entropy also known as measurable uncertainty from a physical source. In many systems, this entropy seeds a deterministic random bit generator (DRBG), which produces these random bits used by all security protocols. The TRNG therefore provides the underlying uncertainty, while the DRBG produces usable output. If either the entropy source or the generation process is weak, attackers may be able to predict or reproduce security values, weakening a system even when it uses strong cryptographic algorithms (Eastlake et al., 2005; National Institute of Standards and Technology [NIST], 2018, 2025). 

## Encryption and Key Generation:
Encryption transforms readable information into ciphertext so that people without the appropriate key cannot read it. Key generation is the process of creating the cryptographic keys used to encrypt, decrypt, sign, or authenticate information. Randomness connects to both: entropy from a TRNG can seed a DRBG, which produces bits used to create encryption keys and other cryptographic values. NIST recommends that cryptographic keys be generated with an approved random bit generator whose security strength matches the protection the key needs to provide (Barker et al., 2020). A key’s length alone is not secure enough; its values must also be difficult for attackers to predict. Any amount of knowledge of a key's values can be used by attackers to recover the remaining value key without having to break the encryption algorithm fully. Encryption methods also have specific requirements for nonces and initialization vectors (IVs). Depending on the method, these values may need to be unique, unpredictable, or both. An example of this is the Debian OpenSSL flaw, which caused affected systems to generate predictable keys. Researchers later found that these vulnerable certificates were still in use months after the issue was disclosed (Dougherty, 2008; Yilek et al., 2009). 

## Authentication:
Authentication is the process of verifying that a person, device, or service is who or what it claims to be. Randomness supports authentication when these systems create challenges, one-time codes, tokens, or session identifiers. A TRNG can supply entropy for these values, while a DRBG can generate them when needed. Passwords can be chosen by users or generated by a password manager. For example, Apple devices can suggest a unique, complex password for supported apps and websites. When a system generates passwords, secure randomness helps make them difficult to guess; a TRNG can provide entropy to the random-number generator that creates them (Apple, n.d.). Machine-generated authentication values still need to be difficult to guess: if a token or session identifier is predictable, an attacker may impersonate a user or take over an active session (Coursera Staff, 2025; Eastlake et al., 2005). 

## Digital Signatures:
A digital signature is created with a private key and checked with the corresponding public key. It helps verify who signed information and whether that information was changed. Some signature schemes, including DSA and ECDSA, use a secret value called a nonce for each signature. If a nonce is reused or generated with exploitable bias, an attacker may recover the private signing key and forge signatures (Heninger et al., 2012; Breitner & Heninger, 2019). RFC 6979 defines a deterministic method for generating DSA and ECDSA nonces, so a new TRNG value is not needed for every signature. The private key itself, however, still needs to be generated securely (Pornin, 2013). 

## Secure Communications:
Secure communications are exchanges of information protected against eavesdropping, impersonation, and message alteration. Protocols such as TLS use cryptographic keys and other values to establish and protect connections. A TRNG can provide entropy to a random bit generator, which produces the bits used to create keys and other protocol values. The requirements vary by value: an encryption nonce, for example, may need to be unique for each use with a key without also needing to be unpredictable. Secure communications therefore depend on strong algorithms and on correctly generated and managed keys and protocol values (BlackBerry, n.d.; Rescorla, 2018). Together, these examples show why randomness matters across cybersecurity. Entropy provides uncertainty, and a random bit generator turns it into usable bits for keys, authentication values, signatures, and secure connections. Weak randomness can undermine any of these protections without requiring an attacker to break the underlying algorithm (Corrigan-Gibbs et al., 2013; Eastlake et al., 2005).
